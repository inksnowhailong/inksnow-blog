# life 页面 · 从计时器到学习承接系统

> 2026-09-22 深度访谈产出，**待批准**。排在「研究线重构」之后做，两者不重叠。

## 根本动机（每个功能都对着它检验）

- 没有兜底、没有人指导、必须靠自己变得更优秀来撑住家庭。
- 系统的用途是**催促自己每天比昨天强一点、每天充实一点，对冲绝望感**。
- 理论底座：《人生十二法则》第 4 条——跟昨天的自己比，不跟别人比；《穷查理宝典》奖励与惩罚的超级反应——有意识地用激励控制自己的脑子。
- 体能债是有意的算计：锻炼本来就苦，拿它当惩罚，惩罚同时是健身。**不是缺陷，不动。**

## 目标

页面现在只测投入（分钟），不测学到了什么。访谈里确认：你要的不是"变强的指标"，而是**持续学到东西这件事被看见、被承接**——fast.ai 的充实感来自被人用能懂的方式教会，并且知道自己在阶梯的哪一级。本期给页面补上这条链：

```
学到一个点 ──> AI 先确认你真会了 ──> 归档到所在方向 ──> 每个方向长出一张知识地图
                                                            │
手机首屏改成今日卡 ──> 记一笔 / 看今天还欠什么，一屏内完成
```

计分规则、账本、体能债本期**不动**（未列入本次拓扑）。

## A · 产出记录

两条写入通道，都经 AI，都**先验证再落库**：

```
Claude Code 会话  ──> AI 判断"他学会了 X" ──> 追问 1~2 句 ──┬─ 答得上 → 记 GOT
                                                           └─ 答不上 → 记 STUCK
手机输入条        ──> "今天搞懂了 X，卡在 Y" ──> AI 按你的口述整理 ──> 出草稿 ──> 你点头 → 落库
```

- 一条记录 = 方向（挂在计划树的哪个节点）+ 一句话 + GOT / STUCK + 日期 + 来源（mcp / web）。
- 复用现有学习日志（`life_events` 的 NOTE 事件挂 `nodeId`），加一个 `tag` 区分 GOT / STUCK；不另建表。**实现计划阶段可推翻**。
- MCP 新增 `life_learned` 工具，描述里明确要求模型：会话里出现"我懂了 / 原来是这样 / 学会了"时，先追问再记；追问不超过两句，口吻轻。
- 聊天能力表新增 `log_learned`，替代现有 `add_log` 里"搞懂了什么"那一半用途；`add_log` 保留给纯过程记录。

## B · 今日卡

- 手机（< lg 断点）首屏只有：日期切换、今天排到的每日项（名字 / 已投入 / 还差多少 / +15 +30 / 补到达标）、当日进度条、底部输入条。
- 不做"与昨天比"的逐日对比（访谈里否掉了）：逐日比较波动大、容易今天比昨天差，与"慢慢变好"的感受相反。
- 路线图、账本、热力图、想法池全部进第二屏（滑或折叠），PC 布局不变。
- 密钥门保留，但记住后不再每次挡在前面（现状已是 localStorage，确认无回归即可）。

## C · 知识地图

- 每个计划树方向节点一页：
  - 已搞懂：GOT 条目按日期正序堆成一列，看得见"在长"
  - 卡在这：STUCK 条目单独挂着，被后来的 GOT 覆盖时自动移入"已搞懂"（同一节点、AI 判定同一知识点）
  - 大纲：AI 把 GOT 条目理成分层大纲（Markdown），每周一次或由 MCP 手动触发；大纲下方标"基于 N 条记录，更新于日期"
- 大纲存 `knowledge_maps`（nodeId, outline, basedOn, generatedOn）；页面从计划树节点详情进入。
- 不做"AI 排下一阶"（访谈里未选），大纲只整理已有，不规划未来。

### C2 · 总体向上（"慢慢变好"的那一眼）——星图

你描述的意象是"一棵在长的树、一张越来越满的星图"。主体选**星图**：越满越好看，几百个点只会更密更亮；树留给单个方向页，叶子少不挤。

- **星图**：一块深色画布，每个计划树方向是一个星座（有名字、有淡淡的连线勾出轮廓），每条 GOT 是一颗星，每条 STUCK 是一颗暗星；星的位置由方向决定、在星座内按时间从中心向外排。最近 7 天新长出来的星带光晕，之后归于常亮。第一眼落在"整片天有多满"，第二眼才是"哪儿新亮了"。
- 星图下方一行小字：`至今 N 颗星 · 投入 H 小时 · 连续 W 周有新星`。累计曲线不再单独画。
- 渲染用 canvas 手绘（项目里有 ECharts，但 `graph` 的默认样式压不住这个意象；canvas 自由度更高）。星图是只读的，点某个星座进入该方向的知识地图页。
- **方向页的树**：一棵小树，主干是方向名，枝是 AI 大纲的一级节点，叶是 GOT 条目；STUCK 挂在枝上显示为枯叶。同样 canvas 或 SVG 手绘，一个方向一棵，不会挤。树下面才是大纲正文与列表。
- 放置：手机第二屏顶部、PC 主列顶部是星图；方向页顶部是树。
- 比较对象仍只有过去的自己，页面上不出现任何外部标尺。

## 已暴露并解决的假设

| 假设 | 结论 |
|---|---|
| 需要更多激励机制 | 否。动机是内在的（学习本身让你高兴），缺的是承接与可见，不是奖励 |
| 奖励与惩罚的设计需要重新审视 | 否。分→元、体能债都是有意按"奖惩超级反应"设计的，本期不动 |
| 体能债把运动变成惩罚是副作用 | 否。这是有意算计：惩罚同时是健身 |
| 缺一个 AI 指导者角色 | 你判断地图 + 今日卡够了，本期不做每周回顾与排下一阶 |
| 产出应是可量化指标 | 否。产出 = "搞懂了什么"一句话，量化只到条数 |
| 用户会主动写日志 | 半。你只会对 AI 说，不会填表；所以所有写入口都是 AI |
| 手机版可以是 PC 的缩放 | 否。手机高频只有两件事，首屏必须只剩这两件 |

## 事前验尸

"三个月后地图还是空的"——你的回答是"不会死，我会用"。记为承诺；相应地本期**不做**任何提醒/推送机制，若三个月后地图确实空着，先回到这一条。
